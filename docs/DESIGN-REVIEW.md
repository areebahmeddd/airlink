# Design Review

The reasoning behind Airlink 1.0.0: the defects review found and what holds against each, the decisions taken and the alternatives set aside, the risks kept on purpose, and what only a board can settle. Read it before changing a rule here, so a closed hole is not reopened and a rejected idea is not proposed again.

**Method.**

- **By area.** Reviewers each took one area (protocol and crypto; relay, clock, sync and mail; the LoRa trunk; boards, Bluetooth and tasks; OTA, release and security; Airhop's side), briefed with the code rather than conclusions, and blind to each other's findings.
- **End to end.** Every pipeline was traced, every number recomputed, and the whole node walked through realistic and hostile scenarios on every board, looking for interactions between parts as much as slips inside one.
- **Verified.** Each finding was traced again in the code and against its source before it was decided. Each behavior fix the host can reach has a test that fails without it, checked by reverting the fix; a fix in device code has a bench step in [TESTING.md](TESTING.md) instead.

**Threat model.** A hostile phone on the mesh; a hostile node or LoRa radio in range, which can forge any field nothing authenticates, replay what it captured, mint identities and jam; someone with the board on a bench; a compromised update channel. None of them can break Ed25519, X25519, ChaCha20-Poly1305 or SHA-256.

## 2. Summary

The wire format, relay rules, sync and courier behavior match Airhop and bitchat-ios byte for byte, and the core is bounded, allocation-free on the packet path and tested on the host under the sanitizers. The serious defects sat where the node meets an adversary, the platform or time: budgets one link could exhaust, a clock one phone could lock or walk, a LoRa trunk that authenticated nothing and a duty limit a power cut broke, an update path one late-crashing image or slow server could hold, and a release path that would have left every board unbootable or unable to read its own settings. Each is fixed and tested; what remains is in sections 5 and 6.

**Nothing has run on a board yet.** Timing, heap headroom, verification speed, radio behavior and power are settled by the runbook ([TESTING.md](TESTING.md)), not by this review (section 6).

Each table gives the risk and what holds against it in the code, ordered by severity. Findings kept as they are, by decision, are in section 5.

### 3.1 Wire, Decoding and Crypto

| ID     | Sev    | Risk                                                                                                                                                                                                                                                                                                           | What holds                                                                                                                                                                                                                                                                                                           |
| ------ | ------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| WIRE-1 | High   | The 32 KiB inflate window kept the previous packet's output, and tinfl checks a match's distance only in its non-wrapping mode, so a 5-byte stream reaching back into old bytes inflated: one frame had a different packet ID each time, slipped dedup, and was relayed though zlib and every client refuse it | The first 32 KiB inflate into a flat buffer that refuses any reference before the packet's first byte. Five zlib-judged streams are vectors under both windows, and `fuzz_frame` compares the IDs the two windows give                                                                                               |
| WIRE-2 | High   | The inflate budget was charged the size a packet claims: 490 bytes of garbage claiming 505 KB spent a second's budget at once, and a stream claiming 1 byte made the inflater produce 32 KiB before refusing it                                                                                                | A packet is admitted on its claim and charged the bytes actually inflated, per link; a flat window stops one byte past the claim                                                                                                                                                                                     |
| WIRE-3 | Medium | A failed SHA-256 (the heap short) gave every packet the same ID, so the node would have dropped all traffic as duplicates                                                                                                                                                                                      | A failed hash yields `0xFF` and fails closed: the packet is malformed, a deposit refused                                                                                                                                                                                                                             |
| WIRE-4 | Low    | bitchat-ios rebuilds a signing preimage through its own encoder, which compresses any payload of 100 bytes or more, so a node-signed payload past that line fails to verify on iOS                                                                                                                             | Only the announce can reach it: `AH_NICKNAME_MAX` is 20, and a `static_assert` keeps the node's announce under `AH_COMPRESS_THRESHOLD`                                                                                                                                                                               |
| WIRE-5 | Low    | No test held the primitives to their standards' own vectors: every crypto check was against the spec generator, a second implementation, or a round trip                                                                                                                                                       | Ed25519, X25519, ChaCha20-Poly1305, SHA-256 and HMAC-SHA256 meet the published vectors of RFC 8032, RFC 7748, RFC 8439, FIPS 180-2 and RFC 4231, and Ed25519, the AEAD and the Noise handshake messages refuse one changed byte. On the host, SHA-256 is OpenSSL's; the device's PSA path rests on Espressif's tests |

**Checked and sound.** v1 and v2 headers, flags, routes and per-type size caps equal bitchat-ios's and Airhop's, with no overflow or out-of-bounds read on any path. The signing preimage is built from the received bytes (TTL zeroed, signature and IS_RSR flags cleared, padded) and matches 19 recorded bitchat-ios packets and the spec generator. Noise XX matches the framework and bitchat-ios: the protocol name as h, an empty prologue, token order, split direction, all-zero DH results refused in constant time, replies read on a copy, and the replay window advanced only after the tag verifies. Secrets are wiped, every PSA operation is finished or aborted, and randomness comes from the hardware RNG with rejection sampling.

### 3.2 Relay, Peers and Links

| ID     | Sev    | Risk                                                                                                                                                                                                               | What holds                                                                                                                                                                                                                       |
| ------ | ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| MESH-1 | High   | One verify budget served the whole node, so about 30 forged files or LEAVEs a second on one link stopped everyone's LEAVE, file, board post and first voice frame from relaying, and new phones from binding       | Each link gets a fair share of `AH_VERIFY_PER_SECOND` (8 on the S3, 13 on the C6, from about 30 ms per Monocypher verify at 160 MHz), with a reserve for pre-relay checks; a sync request past its rate costs no signature check |
| MESH-2 | High   | A session's Noise proof outlived its link: whoever took the same link slot next and replayed the proven phone's announce was handed its mail without a handshake                                                   | A closed link clears the link and direct flag of every session on it                                                                                                                                                             |
| MESH-3 | Medium | Any verified TTL 7 announce rebound a link, so a replay after the dedup window bound the attacker's link to a victim, and a second link could take the victim's direct path, sending its DMs to the attacker alone | A link binds once, to the first identity announced directly over it, and only on a strictly newer announce (every client stamps each announce with the current time); a second link never takes the direct link                  |
| MESH-4 | Medium | Giving up a peer (a full table, a verified LEAVE) released its signing-key pin, so the next announce under its ID could pin another key                                                                            | Pins outlive the table in a ring (`AH_PEER_PINS`), and eviction spares peers with a live link                                                                                                                                    |
| MESH-5 | Medium | Packets outside the freshness window were stored, answered and delivered once the clock was synced                                                                                                                 | They are relayed and counted as stale, never acted on. A fragmented packet is judged from its first piece, and an IS_RSR inside fragments counts as solicited only in reply to the node's own request                            |
| MESH-6 | Low    | A sync reply failing against its author's known key was declined, and since the packet ID does not cover the signature, one forged copy hid the genuine message for hours                                          | A failing reply is forgotten, not declined; only a reply whose author is unknown is declined, until that author's announce. A message relayed while its own check was put off is kept from a later sync reply                    |
| MESH-7 | Low    | A live stream verified once was then relayed on its shape alone whatever link it came over, though its sender and stream ID travel in clear: anyone could send forgeries riding it for a minute                    | The shortcut holds per stream and link, and a closed link's entries are cleared, since its slot is reused; a packet riding a stream over another link is checked as a new one                                                    |

**Checked and sound.** The relay decision transcribes Airhop's `relayDecision`: TTL caps by degree, jitter windows, the directed set, unknown types relayed, and an announce never forwarded at TTL 7 (bitchat-ios would bind the relay's link to the originator). Fanout skips every link of the arrival peer and sends one copy per peer. Dedup keeps three sets, and a failed check is never recorded, so a forgery cannot shadow the genuine packet; that leaves a forgery free to repeat, which is why the verify budget is shared per link (MESH-1). Every table is allocated at creation with an eviction rule. The announce never carries TLV `0x04`, and the node decrypts only DMs addressed to it.

### 3.3 Clock

| ID    | Sev    | Risk                                                                                                                                                                                                                                                                                 | What holds                                                                                                                                                                                                                                                                 |
| ----- | ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| CLK-1 | High   | One phone over 15 minutes off, first to arrive after a reboot, synced the clock; every honest announce then looked stale, the samples that could correct it were dropped with it, and sync, mail and DMs stopped until a reboot                                                      | The 15-minute gate applies only to a confirmed clock, and an unconfirmed one that no fresh phone backs gives way when phones disagree                                                                                                                                      |
| CLK-2 | High   | Voices were counted per identity, which costs nothing to mint, and then per link, which one phone on two connections doubles; a confirmed clock jumped to the median without bound, and one link walked it 0.5 s per sample (14 h in 60 rounds), saving the walked time as the floor | A voice is a link and an identity, whichever is fewer, and a re-sync needs two agreeing voices and more than half. A confirmed clock never jumps: it slews from an allowance of 0.5 s growing at 50 ppm. The saved floor is capped at the restored floor plus elapsed time |
| CLK-3 | High   | Nodes were never a clock source, so a LoRa repeater with no phones never synced, never announced and never bound its links: a chain of nodes carried nothing                                                                                                                         | A node takes time from other nodes' verified announces while no phone is in reach. That time is never confirmed, so it never expires mail or sets the floor                                                                                                                |
| CLK-4 | Medium | One skewed phone after a reboot could expire the whole mailbox, prune sync history and become the floor                                                                                                                                                                              | Mail expiry, history pruning and the floor save wait for a confirmed clock. A floor planted ahead at a fresh node's first boot is overruled for the boot by phones agreeing behind it and outnumbering every other fresh phone                                             |
| CLK-5 | Medium | A confirmed clock refused any voice more than 5 s off, so a node alone for a week at 20 ppm (12 s off) could never be pulled back by one phone, and drifted out of every phone's 2-minute window in about two months                                                                 | How far off a voice may be, and the slew allowance, grow by the 50 ppm drift since a phone last agreed with the clock: a hostile phone still walks it no faster than 50 ppm                                                                                                |
| CLK-6 | Medium | Mail's monotonic hold restarted at every boot and wall-clock expiry waited for two phones, so a solar node rebooting nightly with no two phones in reach kept expired mail for good and its mailbox filled                                                                           | The restored floor plus the node's uptime, a time real time is surely past, expires mail and is saved as the floor while the clock is unconfirmed, so the floor climbs by every boot's uptime. It still lags real time by every hour the node was off (section 5)          |

### 3.4 Gossip Sync

| ID     | Sev    | Risk                                                                                                                                                                                         | What holds                                                  |
| ------ | ------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------- |
| SYNC-1 | Medium | The store's ring overwrote live entries after an exact fit, serving the wrong bytes to a returning phone                                                                                     | The ring accounts for an exact fit                          |
| SYNC-2 | Medium | One store's eviction cursor applied to the whole request, so on a compact board with more than a dozen announcing peers every phone withheld message and group history the node had room for | Each store that gave up room asks for its own history alone |
| SYNC-3 | Medium | A request over LoRa could spend a backlog of trunk transfers on one answer                                                                                                                   | Sync is answered over Bluetooth only                        |
| SYNC-4 | Low    | Announces were held to a requester's since-cursor, which bitchat-ios exempts them from; on a compact node a busy room's cursor withheld the keys the history needs                           | Announces are served past any cursor                        |
| SYNC-5 | Low    | A stored entry larger than the streamed cut's buffer stalled its link's reply for good (unreachable with the shipped settings)                                                               | It is passed over                                           |

**Checked and sound.** GCS matches bitchat-ios (P 7, M = n << P, 10 % trim, MSB-first Golomb-Rice), and a request is answered only at TTL 0, from the bound and signed link peer, at 8 per 30 s.

### 3.5 Courier Mailbox

| ID     | Sev    | Risk                                                                                                                                                                                                                                                                                                                          | What holds                                                                                                                                                                                                                                                                          |
| ------ | ------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| MAIL-1 | Medium | A handover streamed in pieces retired the mail, erasing it from flash, when its last piece was written, even if a middle piece had been evicted or gone stale                                                                                                                                                                 | Every piece carries the attempt's token, and the mail is retired only when all were written                                                                                                                                                                                         |
| MAIL-2 | Medium | Global eviction let four throwaway identities (sixteen with PSRAM) empty the mailbox; nothing bounded flash wear, so a full-rate deposit stream wore the partition out in about a month; and one identity whose mail expires within seconds, or whose envelope's copies it keeps raising, could spend the whole hour's writes | A full mailbox, or a depositor at its quota, refuses, as Airhop and bitchat-ios do. Writes keep to `AH_MAIL_FLASH_KIB_PER_HOUR`, and each depositor, raises of its copies included, to its quota's share of that hour; the build refuses a share too small for the largest envelope |
| MAIL-3 | Medium | Mail was sprayed to any announced peer, so one announcing a neighbor's key took that neighbor's copies                                                                                                                                                                                                                        | Spray goes only to a peer that proved its key on one of its links, or once its session completes                                                                                                                                                                                    |
| MAIL-4 | Medium | A deposit put off for verify budget was lost, its ID already in dedup; mail that left stayed in flash and returned after every reboot                                                                                                                                                                                         | A put-off deposit's ID is forgotten (it is addressed to the node and never relayed), and every envelope that leaves, delivered or expired, is erased from flash through one callback                                                                                                |
| MAIL-5 | Low    | With no confirmed clock, mail already expired by the node's own clock was still handed over and sprayed, and a reboot sprayed the original budget again                                                                                                                                                                       | Expired mail is kept but never sent on, and a changed budget is written back. Mail held past any envelope's lifetime leaves by monotonic time                                                                                                                                       |
| MAIL-6 | Low    | On boards without PSRAM a depositor held one envelope and its second recycled the first, which its sender counts as carried for a day                                                                                                                                                                                         | Each depositor holds two, and a third is refused rather than one dropped                                                                                                                                                                                                            |
| MAIL-7 | Low    | Any cut under way (a long sync reply on another link) held every handover, spray and flood back, even of envelopes that fit one write                                                                                                                                                                                         | Only a cut waits for a cut                                                                                                                                                                                                                                                          |

**Checked and sound.** Handover goes only over a Noise XX session whose static key derives the peer ID, made on a direct link. Lifetimes over 24 hours plus 1 hour of slack are refused, not clamped. Each envelope is one NVS entry, so a power cut leaves the old state or the new one.

### 3.6 LoRa Trunk

| ID      | Sev    | Risk                                                                                                                                                                                                                                                                              | What holds                                                                                                                                                                                                                                                                                                                                                                                    |
| ------- | ------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| LORA-1  | High   | No trunk field was authenticated: a replayed announce under a forged source hijacked a neighbor's link, a forged COMPLETE ended a real transfer as delivered, and a forged power field made adaptive power starve a real neighbor until it was dropped                            | Trunk frame version 1 tags every frame for each node it is for: 8 bytes of HMAC-SHA256 under a pair key from X25519 between the two nodes' static keys, which their IDs name and the beacon carries. A beacon's key is the one thing taken untagged; a claimed power is held between 2 dBm and the region's ceiling                                                                           |
| LORA-2  | High   | The LoRa task derived its pair keys from an identity `app_main` had already wiped, so on a device no tag could ever match. Host tests call the derivation directly and passed                                                                                                     | The trunk keeps its own copy of the secret and the ID, wiped if LoRa fails to start                                                                                                                                                                                                                                                                                                           |
| LORA-3  | High   | A forged beacon cost the node 27 times the attacker's airtime (its announce plus five probes), so seven an hour emptied India's data share                                                                                                                                        | An unverified neighbor gets the node's announce in one round with no probe, and everything sent to unverified neighbors keeps to a quarter of the budget                                                                                                                                                                                                                                      |
| LORA-4  | High   | In India and Southeast Asia presence traffic alone filled the duty budget, and a neighbor that could not hear back drained it without end                                                                                                                                         | Announces cross once per sender per interval scaled by the region (5, 20 and 50 minutes), below text. Two failed transfers hold a neighbor down for 10 minutes, doubling to 2 hours                                                                                                                                                                                                           |
| LORA-5  | High   | Reassembly took the piece size from whichever piece came first, so a short last piece arriving first misplaced every other piece                                                                                                                                                  | The last piece is held aside until a full piece fixes the size                                                                                                                                                                                                                                                                                                                                |
| LORA-6  | Medium | A flood went as one transfer per neighbor                                                                                                                                                                                                                                         | Copies queued within 20 ms join one transfer for up to seven destinations, which answer the asking piece in turn, the answer's airtime plus 100 ms apart, each given up on alone. Ten nodes in range carry a message in at most twenty transfers, not eighty                                                                                                                                  |
| LORA-7  | Medium | In a transfer to several, a COMPLETE answered pieces that did not ask and collided with the next, a beacon or a late answer went while answers were due, and any TX done re-armed the feedback window                                                                             | Only the asking piece is answered and arms the window; nothing of the sender's goes while its answers are due, and nothing of a receiver's while its turn is still to come                                                                                                                                                                                                                    |
| LORA-8  | Medium | Replayed pieces tagged for the node earned answers without limit; answers to unverified sources could take the whole budget and queued answers never expired                                                                                                                      | Answers keep to a third of the budget, those to unverified sources to their quarter; a held answer expires after 12 s, and one for a verified neighbor displaces one for an unverified source                                                                                                                                                                                                 |
| LORA-9  | Medium | The duty ledger reset on every reboot, so a reset loop broke the hourly limit; a node busy just before a power cut ran the hour around it to 1.5 times the budget, and a cut every few seconds sent each boot's beacon unrecorded; a reset while a frame went out lost its charge | The ledger survives resets in CRC-checked RTC memory and power cuts in a flash copy written as the trunk starts and whenever it lacks a sixty-first of the budget; restoring that copy charges the most it can lack, so a loop of power cuts keeps to the limit, and a failed write is tried again. With neither, the hour before is taken as spent. A frame is charged before the radio keys |
| LORA-10 | Medium | Adaptive power never stepped up after a failure; a radio that reset on its own went unnoticed until the transmit watchdog                                                                                                                                                         | A neighbor gets full power after a silent round until a transfer gets through. The packet type is checked before every channel check and transmission, and type and chip mode every 5 s while listening                                                                                                                                                                                       |
| LORA-11 | Medium | A reply beacon owed within 30 s of the last was dropped, so a node rebooting just after waited a whole interval; with eight neighbors, a beacon of seven tags made the next one due at once, and ties always left the same two out in turn, so one lost beacon dropped either     | An owed beacon is put off to 30 s after the last, never dropped. The next beacon is never sooner than an interval after the last, the neighbors tagged longest ago go first, and ties break from a slot that moves on each beacon, so all eight are tagged within two                                                                                                                         |
| LORA-12 | Medium | At a first meeting, or after a hold-down, a node's announce most often reached the other before its key did and was dropped there, leaving that side unbound for a trunk announce interval (up to 50 minutes in Southeast Asia)                                                   | Once a LoRa link binds, the node sends its announce on it again                                                                                                                                                                                                                                                                                                                               |
| LORA-13 | Medium | Public messages under made-up senders, which no far-side phone can verify, crossed the trunk freely: about 70 an hour from one phone spent India's whole budget                                                                                                                   | A public message, location channel message or leave whose sender's announce cannot go ahead of it stays off the trunk. That narrows the flood rather than closing it (section 5)                                                                                                                                                                                                              |
| LORA-14 | Low    | The duty window's 60 buckets left out up to a minute of the hour, and airtime was rounded to the nearest millisecond                                                                                                                                                              | 61 buckets, and the charge rounds up                                                                                                                                                                                                                                                                                                                                                          |
| LORA-15 | Low    | The US profile's 30 dBm left 0.2 dB of power density margin; the lowest setting through the Heltec V4's front end exceeded the `sea` limit with a large antenna                                                                                                                   | The US profile stops at 28 dBm conducted. A board whose lowest output is over the limit does not start its trunk                                                                                                                                                                                                                                                                              |
| LORA-16 | Low    | A replayed asking piece, its tag moved to a late turn (tags do not cover their order), pushed the queued answer back each time, and a waiting answer holds every frame of the node's own: one radio at a third of the duty silenced a node                                        | A newer answer keeps a turn still to come, and its age, and none is queued once the answer share is spent                                                                                                                                                                                                                                                                                     |
| LORA-17 | Low    | A packet the trunk delivered, and acknowledged, was dropped when the mesh task's queue had four slots or fewer free, and its sender never sent it again                                                                                                                           | Trunk frames wait for a slot as control events do                                                                                                                                                                                                                                                                                                                                             |

**Checked and sound.** SX1262 errata 15.1, 15.2 and 15.4 are applied (15.3 does not arise with explicit headers), with per-band image calibration, the TCXO, DC-DC, the private sync word and LDRO only at long symbol times. The ISR only notifies, BUSY waits time out, and the radio is recovered in place. Airtime matches AN1200.13, and every emission goes through one charge point. The Heltec V4's SX1262 is never driven above 21 dBm. There is no default region.

### 3.8 OTA, Release and Physical Security

| ID     | Sev      | Risk                                                                                                                                                                                                                                               | What holds                                                                                                                                                                                                                                                                      |
| ------ | -------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| SEC-1  | Critical | NVS encryption was keyed to an HMAC eFuse key, but the release bootloader takes the lowest key blocks first and burns their read protection, so every release board would have aborted every boot with serial flashing already disabled            | NVS keys come from the flash-encryption scheme: generated on first boot into an encrypted `nvs_keys` partition, with no eFuse step, so the web flasher works                                                                                                                    |
| SEC-2  | High     | With Secure Boot on, ESP-IDF leaves the bootloader out of `flash_args`, so the merged image left offset 0 empty and no release board from the web flasher would boot                                                                               | The bootloader is merged explicitly, and signing refuses an image whose offset 0 does not parse as one                                                                                                                                                                          |
| SEC-3  | High     | Every OTA manifest cost an Ed25519 verify outside any budget, so a flood from anything claiming to be a node kept the mesh task busy until the task watchdog rebooted it                                                                           | One manifest per link per 10 s, charged before the verify; the event drain is capped and yields each second                                                                                                                                                                     |
| SEC-4  | Medium   | Secure Download Mode still writes flash, so a board in hand could erase its settings or garble `otadata`; provisioning was trust on first use, and a typo in the owner key was permanent                                                           | `lock yes` burns `DIS_DOWNLOAD_MODE` on a release board and refuses until the owner key is set; `owner` takes the key with its fingerprint                                                                                                                                      |
| SEC-5  | Medium   | `esp_ota_begin` erases the record of a rolled-back image, so a node fetched it again forever; a power cut during a trial refused a good version for good                                                                                           | The refused version lives in the node's own NVS namespace and only rises. Only a fault (a panic or a watchdog), or three power cuts or restarts, refuses a version, and an image fetched whole and then refused by its checks is not fetched again from that server for an hour |
| SEC-6  | Medium   | Core dumps were never written (nothing pulled the component in), would have sat in plaintext on release builds, and could not be read back there; a panic printed registers                                                                        | Core dumps are written to encrypted partitions; `status` shows the reset reason and `crash` prints a summary, never registers                                                                                                                                                   |
| SEC-7  | Medium   | The web flasher loaded its tools unverified, served any merged image, and was published from whichever branch dispatched it                                                                                                                        | ESP Web Tools are vendored from npm's tarball against its integrity; each merged image is checked against the CI-attested build, refusing any byte outside it, its signature blocks and the manifest; the flasher builds from the tag                                           |
| SEC-8  | Medium   | A trial ended at the first bound link, a phone included, within seconds: an image that crashed minutes later was kept, offered on at once, and spread a crash loop through a release fleet that no wire could reach                                | A trial lasts 15 minutes with a bound link (`AH_OTA_TRIAL_MIN`), an image on trial is never offered, and a failed attempt to mark it kept is tried again                                                                                                                        |
| SEC-9  | Medium   | `tools/check_merged.py` and `tools/release_sign.sh` took the image list and offsets from the build's `flash_args`, which nothing attests: one more line let planted bytes (a settings partition) pass as CI's build                                | The layout comes from the attested partition table alone, and the signing script runs the same check on what it cuts                                                                                                                                                            |
| SEC-10 | Medium   | A transfer had no progress floor: a hostile node answering each request with one byte, or dropping the link before any check and offering again, held an update off for months, and a garbage image held that release off every server for an hour | A piece must be the size asked for; a transfer slower than 512 bytes a second after a minute, or dropped by its server while that slow, is given up; and a failure holds off only the server that caused it                                                                     |
| SEC-11 | Low      | The Secure Boot RSA line set a promptless symbol and did nothing; a factory reset left the core dump and raced the mesh task                                                                                                                       | `CONFIG_SECURE_SIGNED_APPS_RSA_SCHEME` is pinned. A reset sets a mark, and the next boot erases mailbox, core dump and settings before any task starts                                                                                                                          |
| SEC-12 | Low      | A rollback was marked judged before its refusal was written, so a power cut between the two forgot the refusal; marking an image kept could fail unnoticed, leaving it on trial for good                                                           | The refusal is written first; marking kept is checked and retried                                                                                                                                                                                                               |
| SEC-13 | Low      | A suffixed tag (`v1.0.0-rc1`) built under the plain version's OTA number; the flasher workflow checked out whatever ref bore the tag's name, a branch included                                                                                     | The release workflow refuses any tag but `vX.Y.Z`; the flasher checks out `refs/tags/`                                                                                                                                                                                          |
| SEC-14 | Info     | `status` said locked once the flag was written, though the eFuse burn after it might have failed                                                                                                                                                   | It says when the serial loader is still open                                                                                                                                                                                                                                    |

**Checked and sound.** A manifest's signature and board are checked before `esp_ota_begin` and the image hash before `esp_ota_end`; only a strictly newer version is taken, and none while an image is on trial. Release images are built twice and compared, attested, and signed outside CI. Actions are pinned to commits with least-privilege permissions and no `pull_request_target`; the tools image is pinned by digest and pip installs by hash.

## 4. Design Decisions

| Decision                                                                                           | Why                                                                                                                            | Set aside                                                                                                                                                                    |
| -------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A pure C protocol core with no ESP-IDF in it                                                       | The code tested on the host under the sanitizers is the code that ships                                                        | Platform code mixed into protocol logic                                                                                                                                      |
| Monocypher, vendored, for Ed25519, X25519 and ChaCha20-Poly1305; SHA-256 on the chip through PSA   | One build on host and device; Mbed TLS 4 has no Ed25519                                                                        | libsodium (the host would test a different build); noise-c (unmaintained)                                                                                                    |
| Pre-relay checks for LEAVE, files, board posts and live media, within a per-link budget            | bitchat-ios and Airhop check them there, so a node does not re-flood what phones drop                                          | A negative cache of failed checks: a forgery varies for free, and one keyed on the packet ID would let a forgery shadow the genuine packet                                   |
| Time only from verified direct announces, with no authority bit                                    | A node signs its own announce, so any claim of authority is free and could push phones outside the ingress window              | A per-identity voice alone (identities cost nothing); trusting a claimed clock source                                                                                        |
| The 15-minute announce window, once the clock is confirmed, kept wider than the phones' 2 minutes  | A phone a few minutes off still binds and gets its mail and sync                                                               | Holding announces to 2 minutes, which would strand such a phone at the node too                                                                                              |
| Stale packets still relayed over Bluetooth                                                         | A node's time may rest on one phone or on other nodes; relaying never depends on it, and fresh junk costs an attacker the same | Dropping before relay once the clock is confirmed, as the phones do                                                                                                          |
| No TLV `0x04` in the node's announce                                                               | A fixed node listing the phones beside it broadcasts where people are                                                          | bitchat-ios's practice of always sending it                                                                                                                                  |
| Prekey bundles relayed but not cached                                                              | A per-owner store does not fit the compact profile                                                                             | Caching them as bitchat-ios does                                                                                                                                             |
| Two table profiles, chosen by PSRAM ([MEMORY.md](MEMORY.md))                                       | Boards without PSRAM keep every rule with smaller tables, never different behavior                                             | One profile sized for the smallest board                                                                                                                                     |
| Each LoRa neighbor is a mesh link, and multi-hop is the ordinary TTL flood                         | Dedup, fanout and priority stay the Bluetooth ones; routes at the trunk can be hijacked by replay                              | Trunk-level routing and forwarding                                                                                                                                           |
| One fixed modulation per region                                                                    | Two nodes can never be stranded on different settings                                                                          | Link adaptation, which trades that for range                                                                                                                                 |
| The strictest reading of each region's rule, and no default region                                 | No build is illegal anywhere by default. In the US only a 500 kHz channel meets 15.247 as a fixed channel                      | A 125 kHz US channel (meets no rule); per-country Southeast Asian profiles; SF8 in Australia (10 dB of range for a reading the US profile already rests on)                  |
| Trunk tags from the static X25519 keys the node IDs already name                                   | No handshake and no airtime of its own: 8 bytes per destination                                                                | Signed beacons (64 bytes on every one); admission by fleet, which would wall off other owners' nodes                                                                         |
| Media, files and sync stay off LoRa                                                                | A tight region's budget is minutes of air an hour                                                                              | Carrying whatever the mesh offers                                                                                                                                            |
| OTA link-local at TTL 0, on Bluetooth between verified nodes, with a manifest that names the board | An image over LoRa would take days of duty; a board-named manifest keeps one board's image off another                         | Updates over the trunk or through phones                                                                                                                                     |
| An owner key per fleet, written once in NVS; the Secure Boot key separate; both kept out of CI     | One leaked key does not give the other's power, and a fleet is not tied to one build                                           | An owner key compiled into the image                                                                                                                                         |
| NVS encryption through flash encryption                                                            | SEC-1                                                                                                                          | The HMAC scheme with eFuse read protection left open, which Espressif warns exposes the Secure Boot digest; burning a key before first boot, which the web flasher cannot do |
| Provisioning at the serial console, ending in `lock yes`                                           | No per-board image, and the lock also closes download mode                                                                     | Prebuilt NVS images per board                                                                                                                                                |
| No remote wipe                                                                                     | A node holds no plaintext and no one's keys; `factory-reset` at the console covers it                                          | A remote command, which would be an attack surface for nothing                                                                                                               |
| The ESP32-C6 as the second target                                                                  | 512 KB of SRAM                                                                                                                 | The ESP32-C5: 384 KB, and its CPU capped at 160 MHz under flash encryption                                                                                                   |
| Separate images for the Heltec V4 and V4-R8                                                        | Different PSRAM modes and Vext pins; a release image's first boot burns its eFuses before the app could tell the two apart     | Detecting the chip at boot, too late for a release image's first boot                                                                                                        |

## 7. bitchat-ios Upstream Gaps

The node does nothing to work around these; they are recorded so nobody tries.

- bitchat-ios verifies a received packet by re-encoding it, and its encoder re-compresses, so a compressed signed packet from another encoder fails to verify there whatever a relay does (Airhop's PROTOCOLS section 2.2).
- Its directed v1 fragments come out one byte over the link limit.
